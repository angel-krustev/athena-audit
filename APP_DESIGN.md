# Athena Audit — Application Design

## Overview

Athena Audit tracks every Athena query execution in your AWS account, enriching raw CloudTrail logs with query metadata from the Athena API. It is specifically designed to support **IDC (Identity Center) workgroups** using Trusted Identity Propagation (TIP), where CloudTrail redacts query text and standard IAM access is insufficient.

## Architecture

```
                          ┌─────────────────────┐
                          │   AWS CloudTrail     │
                          │  (S3 JSON logs)      │
                          └─────────┬───────────┘
                                    │ automatically written by AWS
                                    ▼
┌──────────────┐          ┌─────────────────────┐
│  Athena API  │          │  cloud_trail table   │
│  (all query  │          │  (external table     │
│  executions) │          │   pointing to S3)    │
└──────┬───────┘          └─────────┬───────────┘
       │                            │
       │ History Lambda             │ Events Lambda
       │ (01:00 UTC daily)          │ (02:00 UTC daily)
       ▼                            │
┌──────────────┐                    │
│ history table │                    │
│ (JSON on S3) │────────────────────┤
└──────────────┘        JOIN        │
                                    ▼
                          ┌─────────────────────┐
                          │   events table       │
                          │  (Parquet on S3)     │
                          └─────────────────────┘
```

## Components

### 1. History Lambda

**Source:** `src/athena_history.py`  
**Schedule:** Daily at **01:00 UTC**  
**CloudFormation:** `cloudformation/athena_history_cloudformation.yaml`  
**Timeout:** 900 seconds (15 minutes)

**Purpose:** Collects raw query execution metadata from the Athena API for a single day and writes it to S3 as gzipped JSON.

**Flow:**
1. Defaults to processing **yesterday's** queries; accepts an optional `day` parameter for a specific date
2. Lists all Athena workgroups, filtered by the `WORKGROUPS_FILTER` environment variable
3. For each workgroup, pages through **all** query IDs via `ListQueryExecutions`, then fetches details with `BatchGetQueryExecution` (50 IDs per batch), filtering to the target date
4. For IDC workgroups: first tries IAM access; if it fails, automatically retries with a TIP-authenticated client (via `cihi_auth`)
5. Writes one `.json.gz` file per workgroup per day to S3

> **Note:** The Athena API does not support date filtering on `ListQueryExecutions`, so the Lambda must page through all available IDs (~45 days of retention) to find queries matching the target date.

**S3 path:** `s3://{AUDIT_BUCKET}/{HISTORY_FOLDER}/region={region}/day={YYYY-MM-DD}/workgroup={name}/data.json.gz`

**TIP Authentication (for IDC workgroups):**
- Reads IdP tokens from AWS Secrets Manager (`IDC_SECRET_ARN`)
- Uses `cihi_auth` module to perform credential exchange via OIDC → Intermediary Role → Final Role
- Produces a boto3 session authenticated as the TIP identity
- Falls back gracefully to IAM if TIP is not configured

### 2. Events Lambda

**Source:** `src/athena_events.py`  
**Schedule:** Daily at **02:00 UTC** (1 hour after History Lambda)  
**CloudFormation:** `cloudformation/athena_events_cloudformation.yaml`

**Purpose:** Joins CloudTrail identity data with History query metadata to produce a complete enriched audit record in Parquet format.

**Flow:**
1. Defaults to processing **yesterday**; accepts an optional `day` parameter
2. Creates the database and tables if they don't exist (with `force_recreate` option, which backfills the last 14 days)
3. Adds a CloudTrail partition for the target day
4. Runs `MSCK REPAIR TABLE` on the history table to discover new partitions
5. Executes an `INSERT INTO events SELECT ... FROM cloud_trail LEFT JOIN history` query
6. Filters out queries generated by the audit system's own Lambda roles

### 3. History Fargate Task (optional)

**Source:** `src/run_history.py` (entrypoint), `src/athena_history.py` (logic)  
**Schedule:** Daily at **01:00 UTC** (via EventBridge Scheduler → Step Functions → ECS Fargate)  
**CloudFormation:** `cloudformation/athena_history_fargate_cloudformation.yaml`  
**Docker:** `Dockerfile`

**Purpose:** Alternative to the History Lambda for workloads that exceed the 15-minute Lambda timeout. Runs the same `create_history_day()` logic in a Fargate container with no time limit.

**Resources created:**
- ECR repository (keeps last 5 images)
- ECS Cluster with Container Insights
- Fargate Task Definition (ARM64, 512 CPU / 1 GB RAM)
- Step Functions state machine (runs the Fargate task with retry: 2 retries, 60s backoff)
- EventBridge Scheduler (daily at 01:00 UTC)
- IAM roles mirroring the Lambda permissions

**Environment variables:**
| Variable | Description |
|---|---|
| `TARGET_DAY` | Date to process (default: yesterday) |
| `TARGET_WORKGROUP` | Process a single workgroup (optional) |
| `FORCE` | Set to `true` to clear existing data before re-collecting |

**Manual execution:**
```bash
# Via Step Functions
aws stepfunctions start-execution \
  --state-machine-arn <state-machine-arn> \
  --input '{"day": "2026-03-01"}'

# Via Docker locally
docker run --rm \
  -e AWS_REGION=us-east-1 \
  -e AUDIT_BUCKET=<bucket> \
  -e HISTORY_FOLDER=athena_audit/history \
  -e TARGET_DAY=2026-03-01 \
  <image-uri>
```

> **When to use Fargate vs Lambda:** Use the Lambda for normal daily loads. Switch to Fargate if you have many workgroups with high query volumes that cause Lambda to time out at 15 minutes. Both can coexist — disable the Lambda's EventBridge schedule and enable the Fargate schedule, or vice versa.

### 4. CloudTrail

**Not managed by this application.** CloudTrail must be independently configured to log management events to an S3 bucket. The `cloud_trail` table is an external Athena table that points to the CloudTrail S3 location.

## Tables

### `cloud_trail` — External Table (read-only)

**Populated by:** AWS CloudTrail (automatically)  
**Format:** JSON (CloudTrailInputFormat)  
**Partitioned by:** `region`, `year`, `month`, `day`

| Column | Description |
|---|---|
| `userIdentity` | STRUCT containing type, ARN, principalId, sessionContext.sourceIdentity, onBehalfOf.userId |
| `eventTime` | ISO 8601 timestamp of the API call |
| `eventSource` | Always `athena.amazonaws.com` for Athena queries |
| `eventName` | API action (filtered to `StartQueryExecution`) |
| `sourceIpAddress` | Caller's IP address |
| `userAgent` | Client application identifier |
| `requestParameters` | JSON containing queryString, workGroup, queryExecutionContext.database |
| `responseElements` | JSON containing queryExecutionId |

**Key limitation:** CloudTrail **redacts** `queryString` to `***OMITTED***` for TIP/IDC sessions.

### `history` — JSON Table

**Populated by:** History Lambda  
**Format:** Gzipped JSON (JsonSerDe)  
**Partitioned by:** `region`, `day`, `workgroup`

| Column | Source | Description |
|---|---|---|
| `query_id` | `QueryExecutionId` | Unique query execution identifier |
| `query` | `Query` | Full SQL query text (not redacted) |
| `data_scanned` | `Statistics.DataScannedInBytes` | Bytes scanned |
| `status` | `Status.State` | `SUCCEEDED`, `FAILED`, or `CANCELLED` |

### `events` — Parquet Table (primary audit table)

**Populated by:** Events Lambda (INSERT ... SELECT from cloud_trail JOIN history)  
**Format:** Parquet  
**Partitioned by:** `region`, `day`

| Column | Source | Description |
|---|---|---|
| `query_id` | CloudTrail | Unique query execution identifier |
| `event_time` | CloudTrail | Timestamp of the query submission |
| `source_identity` | CloudTrail | The real user identity (e.g., `angelkrustev`) — from `sessionContext.sourceIdentity` |
| `on_behalf_of_user_id` | CloudTrail | IDC user ID — from `onBehalfOf.userId` |
| `user_identity_type` | CloudTrail | Identity type (`Root`, `IAMUser`, `AssumedRole`) |
| `user_identity_principal` | CloudTrail | Principal ID of the caller |
| `user_identity_arn` | CloudTrail | Full ARN of the caller |
| `source_ip` | CloudTrail | Caller's IP address |
| `user_agent` | CloudTrail | Client application identifier |
| `workgroup` | CloudTrail | Athena workgroup name |
| `query` | History (fallback: CloudTrail) | Full SQL query text |
| `database` | CloudTrail | Session's default database context |
| `status` | History | `SUCCEEDED`, `FAILED`, or `CANCELLED` |
| `data_scanned` | History | Bytes scanned by the query |
| `cost` | Computed | Estimated query cost in USD — calculated as `data_scanned / 1 TB * COST_PER_TB`. Rate is configurable via the `COST_PER_TB` environment variable (default: `5.00`) |

## Why the JOIN Matters

| Data point | CloudTrail | History | Events (merged) |
|---|---|---|---|
| Who (sourceIdentity) | ✅ | ❌ | ✅ |
| IDC user ID (onBehalfOf) | ✅ | ❌ | ✅ |
| IP address | ✅ | ❌ | ✅ |
| Query text | ❌ (redacted for IDC) | ✅ | ✅ |
| Status (SUCCEEDED/FAILED) | ❌ | ✅ | ✅ |
| Data scanned | ❌ | ✅ | ✅ |
| Cost estimate | ❌ | ❌ | ✅ (computed) |
| Workgroup | ✅ | ✅ | ✅ |

The **events table** is the primary table for auditing — it combines the best of both sources.

## Filtering

The events INSERT query filters out:
- Non-Athena events (`eventsource != 'athena.amazonaws.com'`)
- Non-query events (`eventname != 'StartQueryExecution'`)
- Queries generated by the History Lambda role (`%AthenaHistoryLambda%`)
- Queries generated by the Events Lambda role (`%AthenaEventsLambda%`)

## Deployment

### Prerequisites
- An AWS CloudTrail trail logging to an S3 bucket
- An S3 bucket for audit data (history, events, query results)
- (For IDC workgroups) `cihi_auth` module and an IDC secret in Secrets Manager

### Scripts
- `bin/package.sh` — Builds the Lambda deployment package (ZIP)
- `bin/deploy.sh` — Deploys both Lambda CloudFormation stacks (and optionally the Fargate stack)
- `bin/build_and_push.sh` — Builds the Docker image and pushes it to ECR (for Fargate deployment)
- `bin/create_idc_secret.sh` — Creates/updates the Secrets Manager secret for TIP tokens

### Configuration
Environment-specific config files in `config/` (e.g., `sandbox.json`, `dev.json`, `prod.json`):

| Parameter | Description |
|---|---|
| `Region` | AWS region |
| `HistoryStackName` | CloudFormation stack name for the History Lambda |
| `EventsStackName` | CloudFormation stack name for the Events Lambda |
| `CodeBucket` | S3 bucket for Lambda code packages |
| `AuditBucket` | S3 bucket for audit data output |
| `CloudTrailBucket` | S3 bucket where CloudTrail logs are stored |
| `CloudTrailFolder` | S3 prefix for CloudTrail logs |
| `DatabaseName` | Glue database name for audit tables |
| `HistoryFolder` | S3 prefix for history data |
| `EventsFolder` | S3 prefix for events data |
| `REGIONS` | Comma-separated list of regions to monitor |
| `Workgroup` | Athena workgroup for running audit queries |
| `WorkgroupsFilter` | Filter string for workgroup names (e.g., `idc`) |
| `IdcSecretArn` | ARN of the Secrets Manager secret for TIP tokens |
| `KmsKeyArn` | (Optional) KMS key for S3 encryption |
| `AthenaOutputBucket` | (Optional) Separate bucket for Athena query results |
| `CostPerTB` | (Optional) Cost in USD per TB of data scanned, used for cost estimation. Default: `5.00` |
| `FargateStackName` | (Optional) CloudFormation stack name for the Fargate deployment. Leave empty to skip Fargate |
| `SubnetIds` | (Optional, required for Fargate) Comma-separated subnet IDs with internet access or VPC endpoints |
| `SecurityGroupId` | (Optional, required for Fargate) Security group ID for the Fargate task |

### Manual Invocation

**History Lambda:**
```json
{"day": "2026-03-01"}
{"day": "2026-03-01", "force": true}
{"day": "2026-03-01", "workgroup": "my-workgroup"}
```

| Parameter | Description |
|---|---|
| `day` | Target date (default: yesterday) |
| `force` | Clear existing data before re-collecting (default: false) |
| `workgroup` | Process a single workgroup instead of all (optional) |

**Events Lambda:**
```json
{"day": "2026-03-01"}
{"force_recreate": true}
{"force_recreate": true, "day": "2026-03-01"}
```

| Parameter | Description |
|---|---|
| `day` | Target date (default: yesterday) |
| `force_recreate` | Drop and recreate all tables, then backfill the last 14 days (default: false) |

## Lake Formation

If Lake Formation is enabled in your account (common with IDC), you must grant the following principals access to the audit database and tables:

1. **Events Lambda IAM role** — needs `All` on database, `Select, Alter, Delete, Describe, Drop, Insert` on all tables
2. **Any user/role querying the events table** — needs `Select, Describe` on the tables they access

Tables are created by the Events Lambda. If Lake Formation enforces permissions, new tables require explicit grants before they are queryable.
